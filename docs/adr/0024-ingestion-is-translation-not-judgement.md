# Ingestion is translation, not judgement

Everything that arrives becomes a `Document` before anyone understands it, and the **Receptionist** is the Assistant that understands it. That split has held since the first slice, but it was never under load, because there was only one way for a Document to come into being: a human opened the web application and typed one. The letterbox changes that — a Gmail account the household forwards post to, polled by the Runtime — and the question it forces is *who turns a message into a Document?*

**A Connector does, and no Assistant runs before a Thing exists.** Turning `From:`, `Subject:` and a MIME part into a Document is translation: deterministic, free, and carrying no decision the User would ever want to review. [CONTEXT.md](../../CONTEXT.md) already said where that belongs — *"Classification needs judgement; translation does not and belongs to Connectors"* — and this is the decision to hold that sentence rather than quietly widen the Receptionist to cover the new case. So `runtime/src/watcher/mail.ts` creates Documents from inside the scan loop with no Conversation, no Turn and no LLM, and the Receptionist is triggered by the Document exactly as it is by one a human typed. It cannot tell the difference and has no reason to want to.

The alternative that looks natural and is wrong is to **teach the Receptionist to fetch its own mail** — automate the existing `email.fetch` Manual Connector, grant it, and let the Assistant parse what comes back. It fails three ways at once. It spends an LLM Turn, and therefore money, on `Content-Transfer-Encoding: base64`. It puts raw MIME into a Conversation's context, where it is read once and then carried for the rest of the run. And it inverts the direction of the system: a Trigger is *an event that gives birth to a Conversation*, so an Assistant that goes and finds its own work is an Assistant that must be running in order to discover that it should be running. The whole of [ADR-0004](0004-assistants-suspend-and-resume.md) is that nothing runs while it waits.

A **new Assistant for the post** was refused for a shorter reason: an Assistant is *LLM-driven*, by definition. One with nothing to think about would be a cron job wearing the word, and the first entry in the catalogue that made the definition untrue.

The seam this draws is sharper than the old sentence, because it now has money on one side of it. `document.extractText` pulls the text a PDF already carries — deterministic, free, exact — so the ingest calls it on arrival and most forwarded post is classifiable before the Receptionist is woken. `document.readScan` reads a scan with a vision model, costs money per page, and can invent an amount. The ingest never calls it. **Arrival may translate; arrival may not spend** — because the ingest has no context with which to decide whether a twelve-page attachment is an invoice or a pension provider's annual brochure, and it would pay to find out either way. Deciding that is judgement, it looks at the covering note to do it, and it therefore belongs to the Assistant that was already looking.

This is [ADR-0023](0023-the-runtime-is-the-door-outward.md) from the other side. That one is about a foreign representation leaving through the Runtime on demand; this one is about a foreign representation arriving through it unasked. Both put the translation in the same process for the same reason, and neither lets it into a Turn.

## Consequences

- **Things can now come into being while nobody is looking, and that is the actual novelty.** Every existing mechanism that bounds what follows was already there and is now load-bearing: `maxBirthsPerHour` caps Conversations born per hour, the catalogue's `Enabled` switches `email.receive` off without a restart, and `just pause` stops the Runtime outright. Nothing new was needed, which is the argument that the seam was in the right place.
- **A mailbox is the first untrusted input this system has.** Every other route to a Thing involves the User typing. A public address does not, and an LLM Turn costs money, so a sender allowlist gates the ingest and **empty means nobody** — a list that grants access must never fail open. The startup log prints the sender count rather than the senders, so a misconfigured `0` is visible rather than inferred.
- **The message moves only after every Document has landed.** A crash between the two re-reads the message next poll, finds each `ExternalRef` already present, creates nothing, and moves. A crash the other way round loses the User's invoice silently. `wikai`, solving the same problem against the same Gmail account with entirely different machinery, arrived at the same rule independently — *"Do NOT move the email label yet"* — which is worth more than either design's reasoning alone.
- **The duplicate check is a query against the ThingStore, not a local record of what has been read.** The store is the Authority for Documents ([ADR-0006](0006-one-authority-per-fact.md)); a second store of "mail I have seen" would be a second thing that can disagree with it, and would be wrong every time someone deleted a Document by hand. This is what makes `ExternalRef` — modelled since the beginning and written by nothing until now — earn its place over an opaque hash.
- **Four folders, not a read flag.** `assistants`, `assistants/processed`, `assistants/failed`, `assistants/rejected`. A message that fails must not stay unread, because unread means *retry every minute for ever*; nor may it be marked done, because nothing was created. And rejected mail leaves `incoming` too — the poll takes at most twenty messages, so junk accumulating on a public address would eventually fill every poll and starve a real invoice behind it. Nothing is ever deleted and nothing is ever marked read: every message ends somewhere a human can see it in Gmail without reading a log.
- **`email.receive` is in the catalogue and granted to nobody.** It exists so the User can read it, describe it and switch it off like any other Operation ([ADR-0019](0019-an-operation-is-a-thing.md)). It is `mutating` — it creates Documents — so it is not `clientReadable` and never reachable through the door of [ADR-0023](0023-the-runtime-is-the-door-outward.md). An Assistant granted it could pull the household's post into a Conversation on a whim, and nothing in this design wants that.
- **The Receptionist was not touched by the letterbox at all** — not its prompts, not its Skills, not its Triggers, not its grants. That was the stated test of the design and it is worth recording as an outcome rather than an intention. The reader change *does* edit it, by four lines in the numbered list it already follows, and gives it two Operations. It still gains no Skill: a Skill is judgement, procedure or knowledge, and *"try the free reader, then the paid one, then a human"* is the order in which to reach for three tools. **A capability is not a lesson.**
